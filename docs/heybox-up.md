# HeyBox Up

![HeyBox Up 图标](./assets/heybox-up.svg)

面向小黑盒 Web 端的用户脚本（UserScript）：网页收藏列表不显示“插眼”（CY）条目，但主页收藏总数会把它们算进去。本脚本单独拉取插眼收藏，在收藏页把插眼条目补到收藏列表下方，按帖子去重。社区首页（`/app/bbs/home`）移除右栏热门社区等冗余模块，改为定宽卡片信息流，并支持在右侧预览帖子评论；全站搜索页补齐搜索建议浮层的深色对比度。帖子详情页（`/app/bbs/link/*`）默认进入全屏沉浸阅读，封面优先取站点头图，头图加载失败时回退正文最大图，没有可用图片时取消封面而不留空白占位；标题、正文、媒体与结尾提示避开独占 46px 栏位的底部阅读进度条。正文连续滚动，沉浸模式隐藏站点原生评论区与回复框，改用脚本自建评论侧栏：顶部可发布文章主评论，楼层与楼中楼条目都能就地回复，发送对应的 `reply_id` 与 `root_id`；支持 cube 表情、`Ctrl/⌘+Enter`、字数统计、提交锁、失败重试、取消回复与加载更多，楼中楼全量展示，列表仍可按 `is_cy` 过滤插眼评论；登录账号自己发布的楼层与楼中楼回复额外带“删除”，二次确认后调用站点删除接口，并从列表与评论数同步减去。非沉浸模式下，原生评论区监听评论列自身的滚动，接近底部时加载下一页，不再要求整页滚动。纯视频帖生成独立视频阅读页，帖子尚未渲染时显示可重试的等待页。右侧互动栏可直接点赞、收藏与发布 CY。顶部导航收敛为首页、社区、收藏、文章四个「SVG + 文本」入口，静态与动态两套 SVG 图标随“动态导航图标”开关切换，动态图标仅在开关开启时出现；帖子页纵轴中心左右两侧提供 SVG 上一篇/下一篇箭头，切换走站内路由，不整页刷新。社区页（`/app/topic/link/*`）提供只在该社区内生效的帖子搜索；宽屏社区首页改为左频道、中信息流、右热度三栏工作台。

- 许可：MIT
- 运行环境：ScriptCat / Tampermonkey / Violentmonkey 等 UserScript 管理器
- 适用页面：`https://www.xiaoheihe.cn/*`、`https://xiaoheihe.cn/*`

## 一、设计目标

- 只补网页端缺失的插眼列表，不伪造、不改写站点自己的收藏总数。
- 不复刻第三方插件的代码：签名算法在本脚本内独立实现，避免引入额外依赖或许可问题。
- 默认只读：浏览、收藏补全、评论预览与排序不修改站点数据；只有用户主动点击阅读栏的点赞、收藏、文章评论、楼层回复或 CY 发布时，才以当前登录态调用站点自己的写接口。
- 一个帖子只出现一次：接口按评论维度返回，同一帖子的多条插眼按帖子 ID 去重；新版收藏结构用 `link.linkid`，缺省时回退 `link.id`。
- 自建评论区：沉浸阅读隐藏站点原生 `.link-comment` 与文章回复框，评论按钮打开脚本自建面板（宽 `min(440px, 100vw)`）。悬停或点楼层的“回复”把输入框切到“回复 @昵称”，提交时带上该条评论的 `reply_id` 与所在楼层的 `root_id`；未选回复对象时仍发布文章主评论（`is_cy: 0`，两个关系参数为 `-1`）。楼中楼全量列出，各自带昵称、时间、正文与回复入口。关闭沉浸阅读后恢复站点原生评论区。
- 沉浸阅读优先：帖子详情默认把阅读区放到全屏舞台，封面与标题分层排列，段落、图片与富文本按自然高度连续衔接；右侧互动栏调用站点接口完成点赞、收藏与 CY 发布，评论按需滑出，读完前不让评论区持续分走宽度。没有文章标题图时用正文里的最大一张大图充当封面，图标、表情与过小图片不参与；标题区与结尾同样留出进度条高度，避免文字被固定底栏压住。
- 评论闭环：沉浸阅读的评论侧栏顶部固定一个评论输入框，默认可直接发表文章主评论，点楼层或楼中楼的“回复”后改为回复该条，输入框上方显示“回复 @昵称”并可点“取消回复”回到主评论；支持 cube 表情、`Ctrl+Enter` / `Command+Enter` 发送、1000 字计数、空内容禁用提交与提交锁，失败时保留原文、回复目标并就地显示接口错误、可直接重试，成功后清空输入、跳过缓存重新拉取第一页并同步阅读栏的评论数；接口返回的新评论 id 会用于轮询第一页，直到新评论真的出现在列表里（最多 4 次、间隔 900ms），仍未出现时提示“评论已提交，列表仍待站点同步”。`Esc` 先取消回复目标，再关闭评论区。
- 可逆与可退出：沉浸阅读只是叠加类名与派生 DOM，原生正文、评论区与回复框原地保留；关闭后立即恢复双栏与原生评论区，不改站点数据与路由。
- 输入方式齐全：滚轮、触控板、触摸滑动、方向键、翻页键与快捷键都能前进后退；所有按钮有标签与可见焦点，最小点击区 36px。
- 信息流评论预览：在社区首页不打开帖子也能读评论，默认收起为右缘竖向标签，点信息流里的评论数字才展开；预览只读，回复与点赞通过“打开帖子”回到原生评论区。
- 统一 CY 过滤：帖子页评论工具栏与信息流评论预览共用一个偏好，按接口返回的 `is_cy` 标记隐藏插眼评论；默认不隐藏，用户点“屏蔽 CY”后才生效。阅读栏的 CY 按钮不参与过滤，只负责发布新的插眼。
- 连续阅读：帖子页纵轴中心左右两侧常驻 SVG 上一篇/下一篇箭头。下一篇先按信息流顺序、再按已发现队列寻找未访问帖子，并按最近 12 篇的作者与话题关联度从低到高排序，尽量避开同一作者和相近话题；候选不足时连续拉取信息流下一页补充，相关推荐只在探索失败或队列耗尽后兜底。上一篇由会话浏览记录提供。
- 社区内搜索：社区页（`/app/topic/link/<topic_id>`）的搜索只在该社区内请求，结果与全站搜索分开，不离开当前页面。
- 桌面工作台：宽屏社区首页不再把单列信息流放大居中，而是复用同一份数据排成左频道、中信息流、右热度三栏；窄屏逐步收起右栏和左栏，保留站点原有信息流。

## 二、数据来源

插眼收藏走评论列表接口，路径 `/bbs/app/profile/bbs/comment/list`，关键参数：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `only_cy` | `1` | 只要插眼记录 |
| `filter_type` | `0` | 不过滤类型 |
| `enable_new_style_collect` | `1` | 新版收藏结构 |
| `userid` / `heybox_id` | 账号 ID：Cookie、站点 `storeV2API`、存储、`restore_login` 依次回退 | 当前登录用户 |
| `limit` / `offset` | 20 / 递增 | 分页 |
| `no_more` | `false` | 首页固定值 |

其余基础参数（`os_type=web`、`app=heybox`、`client_type=web`、`version=999.0.4`、`web_version=2.5`、`x_client_type=web`、`x_app=heybox_website`、`x_os_type=Windows`、`device_info=Chrome`）与站点网页端保持一致。

响应判定：`status === "ok"` 时先看 `result` 本身是否为数组，否则依次读 `result.links`、`result.list`、`result.comment_list` 中的数组，都读不到数组就按空页处理。翻页结束优先看 `has_next`（顶层或 `result` 内，`"0"` / `0` / `false` 表示没有下一页，`"1"` / `1` / `true` 表示还有），其次看 `no_more === true`，两者都缺省时以本页没有条目结束。单条记录取以下字段：

- `link.linkid`：帖子 ID（新版收藏结构的字段），缺省时回退 `link.id`，同时用于去重与跳转 `/app/bbs/link/<id>`。
- `link.title`：标题，空值回退“无标题帖子”。
- `link.thumbs[0]`：缩略图，可缺省。
- `text`：插眼时附带的评论内容。
- `create_at`：时间，按秒处理，兼容毫秒值。
- `comment_type`：`1` 记为“回复”，其余记为“评论”。

请求使用页面内 `fetch`，`credentials: include` 携带登录态。账号 ID 按可信度逐层解析：先读 Cookie `heybox_id`，缺失或为 `None`、`null`、`undefined` 这类占位值时回退 `user_heybox_id`；再读站点 `window.storeV2API.read(["account.heybox_id"])` 的快照（要求 `entry.exists === true`）；随后扫本机 `localStorage` / `sessionStorage` 的 `heybox_id`、`user_heybox_id`、`account.heybox_id`（裸数字或 JSON 快照都能取）；最后带签名调 `GET /account/restore_login`，从 `result.account_detail`、`result.profile`、`result` 依次取 ID。站点现在把账号写进 `storeV2API`，Cookie 要等站点自己的 `restore_login` 返回后才落地，只读 Cookie 会在刚进收藏页时误判成未登录，这条链就是为此补齐；解析结果在内存里缓存 60 秒。所有写请求（点赞、收藏、收藏夹列表、文章主评论与 CY）也都使用这条链解析出的账号 ID，而不是只读 Cookie，避免已登录却仍提示登录。全部落空才按未登录处理，不发出插眼请求。接口对 `https://www.xiaoheihe.cn` 返回 `Access-Control-Allow-Origin` 与 `Access-Control-Allow-Credentials`（实测），因此无需 `GM_xmlhttpRequest`，脚本保持 `@grant none`。

信息流评论预览、沉浸阅读自建评论区与 CY 标记共用帖子评论树接口 `/bbs/app/link/tree`，除同一套基础参数外传 `heybox_id`（逐层恢复后的账号 ID）、`link_id`、`is_first`（首页为 `1`）、`page`（从 1 起）、`index=1`、`limit=20`、`owner_only=0`。站点网页端还会带一个空的 `h_src` 参数，脚本在 `link_id` 前补齐，缺省时更容易触发风控。响应 `status === "ok"` 时读 `result.comments`（按楼层分组的数组，每组 `comment[0]` 为楼，后续为楼中楼）、`result.total_floor_num`、`result.link.title` 与 `result.link.comment_num`。单条评论取评论 ID（`comment_id`、`commentid`、`id` 依次回退）、`user.username`、`user.avatar`（兼容拼写 `avartar`）、`text`（去标签后截断 400 字）、`create_at`、`support_num`（兼容 `support_count`）、`reply_count`（兼容 `sub_comment_num`）、`is_cy`（`1`、`"1"` 或 `true` 视为插眼），以及回复关系 `root_id`（兼容 `root_comment_id`、`reply_root_id`）与 `parent_id`（兼容 `reply_to_comment_id`、`reply_comment_id`、`reply_to`、`to_comment_id`）。`-1`、`0` 与空值这类占位关系不当作父级，回退到楼层 ID。楼中楼全部保留并按评论 ID 去重，`quotes` 保留为 `subComments` 的兼容别名。分页在本页为空、没有新增楼层、已加载楼层达到 `total_floor_num`，或缺少总数且本页不足 20 组时停止。

文章连读的连续发现走信息流接口 `/bbs/app/feeds`，参数与站点信息流一致：`pull=0`、`offset`、`dw=660`。没有已存游标时，首次 `offset` 取已渲染信息流之后最近的 30 的整数倍位置，避免从头重复已看过的页面；之后每成功取一页递增 30，并把成功写入的游标按账号存下来。响应 `status === "ok"` 时读 `result.links`，并按站点规则排除 `content_type === 18` 的推广条目；同页重复帖子按 `linkid` 去重。原始 `result.links` 为空数组才视为信息流末尾，整页都被过滤时继续取下一页。脚本先带 `hkey`、`_time`、`nonce` 与 `heybox_id` 请求，签名计算失败、HTTP 失败、网络异常、JSON 解析失败或签名请求返回非登录失败状态时，回退到同一路径的无签名请求；签名请求返回登录失效时不再重试。登录态下该接口的实际返回待确认：未登录公开请求返回 HTTP 200，但 `status` 不是 `ok`；实现按站点网页端同一路径与查询参数对齐。

沉浸阅读的点赞、收藏、文章评论、楼层回复、评论删除与 CY 发布走站点写接口，全部由用户点击触发：`POST /bbs/app/profile/award/link` 传 `link_id` 与 `award_type`（点赞 `1`、取消 `0`）；`POST /bbs/app/link/favour` 传 `favour_type`（收藏 `1`、取消 `2`）、`link_id`、`userid` 与 `folder_id`；`POST /bbs/app/comment/create` 传 `link_id`、`reply_id`、`root_id` 与 `text`。文章主评论与 CY 发布用 `reply_id: "-1"`、`root_id: "-1"`，楼层与楼中楼回复改用该条评论 ID 与所属楼层 ID；主评论与楼层回复传 `is_cy: 0`，CY 发布传 `is_cy: 1`。这些请求共用同一接口与签名参数，区别在 `is_cy` 与回复关系：主评论与楼层回复计入普通评论数与楼层，CY 计入插眼列表。收藏夹列表走 `GET /bbs/app/profile/fav/folders`。删除自己发布的评论走 `POST /bbs/app/comment/delete`，只传 `comment_id`，与创建评论共用同一套签名参数与 `target=heybox_app`，但不带 `_rnd`。网页端 bundle 未暴露该路径，未登录请求返回“非法请求”，真实登录态与 App/Web 端行为仍待确认；脚本只在评论作者 id 与解析出的账号 id 严格相等时才显示删除入口。写请求与站点自身 axios 配置一致，使用 `application/x-www-form-urlencoded;charset=UTF-8` 请求体，query 携带同一套签名参数、评论创建专用的 `_rnd` 与 `target=heybox_app`；`status === "login"` 时统一提示「请先登录小黑盒」。

社区内搜索走通用搜索接口 `/bbs/app/api/general/search/v1`，除同一套基础参数外传 `q`、`search_type=link`、`topic_id`（当前社区 ID）、`offset`、`limit=30`、`is_pull_down=0`；时间筛选非空时追加 `time_range`。响应 `status === "ok"` 时读 `result.items` 与 `result.time_range_list`；`result.items` 里的 `space` 条目只用于占位，`offset` 按 `link` 条数推进，空页或没有新增帖子时停止翻页。空结果提示优先取顶层 `search_not_result_tips`，其次取 `result.search_not_result_tips`。脚本先带 `hkey`、`_time`、`nonce` 请求，失败后回退不带签名的请求，两条都失败才显示错误。

## 三、接口签名

通用接口要求 `hkey`、`_time`、`nonce` 三个签名参数；评论创建接口 `/bbs/app/comment/create` 另要求 `_rnd`。脚本内独立实现：

1. `time = floor(Date.now() / 1000)`。
2. `nonce = md5(time + Math.random()).toUpperCase()`，32 位十六进制。
3. `hkey` 的签名输入为 `time + 1`、归一化路径与 `nonce`：路径归一化为 `/a/b/c/`，三部分分别按 35 字符字母表 `AB45STUVWZEFGJ6CH01D237IXYPQRKLMN89` 映射后交织，截取前 20 个字符作为种子。
4. 种子取 MD5 后，前 5 位映射为 5 字符主体；末 6 位的字符码经列混合与求和后 `% 100` 得到 2 位校验，组合成 `hkey`。

两个容易写错的细节：

- `xtime` 左移结果不能对 255 取模，服务端算法保留高位；截断会算出不同的校验位。
- 列混合只改写前 4 个字节，但求和必须包含原数组全部 6 个字节，否则校验位偏移。

MD5 覆盖 UTF-8 字节，`md5Hex` 与 Node `crypto` 结果一致。`hkey` 的签名输入包含时间、归一化路径与 `nonce`，不包含 `link_id`、`page` 等其他查询参数；评论创建的 `_rnd` 则使用本次请求查询参数中的 `nonce` 与 `_time`。

评论创建的 `_rnd` 复用同一次请求的 `nonce` 与 `_time`。站点当前使用 `15` 作为版本前缀，并以 `Z7mFG4tQp9Ws2LxB8H` 作为 HMAC 密钥；签名为小写十六进制：

```text
message = secret + nonce + _time + ":" + nonce
_rnd = "15:" + lowercaseHex(HMAC-SHA256(secret, message))
```

`_rnd` 只加在评论创建请求上，点赞与收藏沿用原有查询参数。

## 四、UI 与交互

- 收藏页 https://xiaoheihe.cn/app/user/favour/content ：脚本把插眼条目挂在收藏列表（.user-favour__list）下方，按帖子 ID 去重后全部列出，不再对照页面已渲染的同 ID 帖子做过滤。站点先渲染页面骨架、后插入收藏列表时，区块先挂在 `#page-user-favour` 的内容区末尾，列表出现后再挪到它正下方，不会因为挂载顺序而整块缺失。区块使用 Shadow DOM，样式与页面隔离。
- 收藏与文章页右栏：收藏页、文章管理页及文章详情页的右侧只保留二维码、小黑盒加速器、黑盒语音、黑盒工坊与备案信息等推广模块；脚本将这些右栏整体隐藏，并让主列表占满内容区。
- Top navigation: The script takes over `.nav-links` and replaces the original seven text links with four inline SVG links for Home, Community, Favorites, and Articles. Two icon sets are kept: a static one without motion hooks, and an animated one whose stroked paths carry `pathLength="1"` plus the draw animation. Only the animated set is rendered while the setting is on; turning it off or enabling the system reduced-motion preference leaves static icons with no transform, transition, animation, dash array, or dash offset. Motion is limited to devices matching `(hover: hover) and (pointer: fine)` so tapping a link on a touch screen does not leave the icon enlarged, while keyboard focus and press feedback remain available.

## 五、存储与缓存

- 缓存键 `heybox-up.cy.v1:<userid>`，值为 `{ savedAt, items }`。
- 有效期 10 分钟；命中缓存直接渲染，过期后重新拉取。
- 点击刷新会跳过缓存重新请求，成功后覆盖缓存；请求失败时保留当前已显示的结果。
- 单次最多 200 条（10 页），达到上限即停止，避免长列表拖慢页面。
- 缓存按用户隔离，切换账号不会读到他人数据；`localStorage` 不可用时仅本次会话生效。
- 主题偏好键 `heybox-up.theme.v1`，取值为 `system`、`dark`、`oled`、`light`、`paper`、`mist`，仅存本机；旧值 `dark`、`light` 继续有效。
- 屏蔽 CY 偏好键 `heybox-up.hideCy.v1`，取值 `1` 或 `0`，默认 `0`（不隐藏）；仅存本机，帖子页与评论预览共用。
- 首页评论预览偏好键 `heybox-up.commentPreview.v1`，取值 `1` 或 `0`，默认 `1`（开启）；仅存本机，由齿轮设置菜单里的开关写入。
- 导航图标偏好键 `heybox-up.navMotion.v1`，取值 `1` 或 `0`，默认 `1`（动态）；仅存本机，由齿轮设置菜单里的“动态导航图标”开关写入。
- 中栏宽度键 `heybox-up.feedWidth.v1`，取值为 40–76 的整数百分比，默认 `56`；齿轮设置菜单里的分段按钮（40 / 48 / 56 / 64 / 72）与自定义输入框共用这一键，只改 CSS 变量 `--heybox-up-feed-pct`，不重排 DOM。
- 正文行距键 `heybox-up.readerLineHeight.v1`，取值为 1.0–2.2 的倍数（保留两位小数），默认 `1.7`；齿轮设置菜单与阅读页右侧行距面板共用，写入根级 CSS 变量 `--heybox-up-reading-line-height`，只作用于正文文本，标题、代码块、引用与站点卡片保持各自行高。
- 连读顺序键 `heybox-up.feedOrder.v1:<heybox_id>` 与浏览记录键 `heybox-up.postTrail.v1`，只写 `sessionStorage`，关闭标签页即清除；信息流顺序最多保留最近 600 条。连续发现另用 `heybox-up.feedQueue.v1:<heybox_id>`（最多 80 条待读候选）、`heybox-up.feedCursor.v1:<heybox_id>`（下一次 `/bbs/app/feeds` 的 `offset`）、`heybox-up.feedSeen.v1:<heybox_id>`（最多 600 个本次会话已见帖子）与 `heybox-up.feedRecent.v1:<heybox_id>`（最近 12 篇的作者与话题元数据）；没有 `heybox_id` 时后缀为 `:anonymous`。这些键同样只写 `sessionStorage`，关闭标签页即清除；切换账号后读取各自的状态，不会沿用上一个账号的队列与游标。插眼区块只响应收藏页 URL 的 `#heybox-up-cy` 锚点。
- 评论树由脚本按 `linkId + accountId + page` 缓存在内存里，最多 24 页、2 分钟失效；第一页只接受 15 秒内的缓存，发布文章主评论或删除评论后该帖缓存进入 10 秒冷却（既不读也不写），期间页面一律回源并轮询到目标评论出现或消失；评论内容不落盘，排序仍由站点原生组件管理，脚本不保存排序状态。
- 社区内搜索不写 `localStorage`：关键词、时间筛选与已加载结果只保存在当前页面的内存里，刷新或离开页面即清空。
- 桌面工作台不写存储：频道列表与热门排行每次按当前 DOM 重新计算，不缓存到本机，也不跨页面保留。

## 七、运行时架构

- 单一页面运行时：脚本仍以单个 `dist/heybox-up.user.js` 分发，源码在 `scripts/heybox-up/` 内按签名、存储、请求、样式、页面调度、主题、评论预览、沉浸阅读与路由工具分模块，由 esbuild 打包成一个自包含文件；不引入框架，也不在运行时加载外部模块。
- 路由感知调度：所有页面同步任务共用一个 `MutationObserver`，每个任务声明适用路由与 DOM 区域。路由切换时强制执行一轮清理，平时只有相关区域变化才唤醒对应任务，避免文章页的观察器为首页或收藏页重复工作。
- 显式请求生命周期：所有 JSON 请求共用 15 秒超时封装；评论预览、阅读器评论、链接状态、社区搜索与收藏夹列表分别持有 `AbortController`。切换帖子、社区、预览或离开路由时取消旧请求，并把过期响应丢弃。
- 有界缓存：评论树按 `linkId + accountId + page` 缓存，最多 24 页、2 分钟失效，第一页额外收紧到 15 秒；发布文章主评论、删除评论或发布 CY 后只让对应帖子进入 10 秒冷却，冷却期内读写都回源。收藏列表仍按用户隔离并使用 10 分钟缓存。
- 共享基础能力：`localStorage` / `sessionStorage` 经同一访问器提供内存降级与 JSON 读写；样式优先写入构造样式表，不支持时回退到 `<style>`；状态样式表与内容样式表分别按 ID 持有。
- 阅读器热路径：进度节点、正文源节点、原生互动按钮和阅读状态均缓存；滚动进度只更新文本与进度条，阅读比例每 400ms 合并一次，并在渲染、退出、`pagehide` 与页面隐藏时强制落盘。正文分页先写入 `DocumentFragment`，再一次性挂载。
- 主题扫描分级：主题变量负责主体表面，DOM 兜底扫描只处理站点写死的近白底色与暗字；扫描复用单次计算样式与祖先底色缓存，并在浏览器空闲时执行。
- 可回退渲染：沉浸阅读的评论区固定使用脚本自建面板，站点评论节点缺席时不再依赖它；Vue 路由、站点分页与写接口不可用时保留站点原生路径或明确的失败态，不伪造成功状态。

## 八、限制与解决方案

下表按根因合并重复项，逐项记录当前版本仍存在的限制、最优可行方案与落地状态。`固有约束` 表示不能在不伪造数据或绕过站点权限的前提下消除；`部分缓解` 表示已有降级路径，但仍依赖站点结构。

### 8.2 现行细则

- 不改站点收藏总数；该数字由服务端 `bbs_info.favour_num` 计算，脚本只能解释差异，不能修正。
- 收藏页的插眼条目由脚本另插节点，不是站点返回的数据；节点挂在列表容器外，站点分页、排序与计数不受影响。站点改版换容器或类名时插入会失效。
- 单用户上限 200 条；更多插眼需要分页按钮，当前未实现。
- 搜索只覆盖已拉取并缓存的条目，不会额外请求服务端；200 条上限同样作用于搜索范围。
- 接口字段与签名规则由站点控制，改版后可能失效；失效时以“加载失败”提示，不会显示假数据。
- 评论预览只读，不能回复、点赞或展开楼中楼；这些交互只在帖子页的原生评论区提供。
- 预览依赖登录态与 `link/tree` 接口的风控策略：未登录或触发验证码时返回 `show_captcha` 等状态，面板显示失败原因，需要打开帖子查看。
- 预览按楼层分页，楼中楼随所在楼层返回并全部显示；评论触发入口依赖 `.bbs-new-style-bottom__comment` 与 `.content-list__comment` 类名，站点改版后需同步选择器。
- 悬停切换只在面板展开时生效，鼠标需在卡片上停留 600 毫秒以上；每次切换都会请求一次评论接口，长时间来回划过信息流会累积请求，触发风控时面板显示失败原因。
- 自动预览依赖 `#page-bbs-community .bbs-home__content-list` 容器与其中首个 `a[href*='/app/bbs/link/']` 链接；容器或链接结构变化时不会自动带出评论，需点评论数字手动切换。关闭开关后脚本不拦截评论数字，恢复站点原生跳转。
- 脚本未在真实登录态页面内做过端到端点击验证；DOM 逻辑依赖 Shadow DOM 与 `fetch` 的常规行为。
- 站点 CSP 目前允许内联样式；若收紧到禁止 `style-src` 内联，收藏区块的样式需要改为构造样式表。
- 深色模式基于站点现有类名覆盖，站点改版后可能出现未覆盖的浅色块或正文；反馈时请附页面地址与截图。
- 帖子页与收藏页的部分内容需要登录才能渲染，深色样式按站点样式表选择器覆盖，未在登录态逐页点击验证。
- 宽屏布局只在 ≥1200px 生效，依赖站点 `#app > main`、`section`、`.layout-normal` 与 `#page-bbs-community main.list` 结构；站点改版换容器后需要同步选择器。
- 沉浸阅读覆盖图文帖（`.hb-bbs-image-text`）、文本帖（`.hb-bbs-post`）与纯视频帖（`.hb-bbs__video`），纯投票帖仍走站点原布局。正文分块依赖 `.image-text__content`、`.post__content` 的块级结构；站点改版换容器后需要同步选择器，否则只会显示封面与结尾。视频帖若暂时读不到 `<video>` 或 `<source>`，阅读器先显示等待页，9 秒后提供“重试 / 查看原帖”，源节点出现后自动替换。
- 正文分块会克隆静态 HTML，链接可直接点击；内嵌组件里的按钮按“类名 + 文本”转发给原生按钮，组件若使用纯图标按钮或画布交互，克隆页上的表现可能与原页不同。正文中每个可见的 `iframe`、`video`、`audio`、`embed` 与 `object` 会各自复制为独立阅读页；同一容器内的多个播放器按原顺序拆页，`.iframe` 包装容器缺失的宽或高独立回退到子播放器的声明值。含文字与播放器的段落、`div`、`section` 与 `article` 保留为富文本页，原生播放器在阅读期间暂停并静音。关闭阅读器时只恢复未被站点再次写入的来源；站点清空、移除或写入任何新值的来源保持站点值，即使新值等于暂停占位。外部站点是否允许在克隆页中播放仍由提供方决定（待确认），站点自身隐藏的嵌入不会进入阅读页或富文本克隆。
- 沉浸阅读用 `display: none` 隐藏站点原生评论区与回复框，DOM 不搬动；关闭后恢复原双栏与原生评论区。自建评论面板只读取评论树，不写入站点评论 DOM。
- 正文是连续滚动，没有页高上限；`100dvh` 不可用的旧浏览器退回 `100vh`。
- 阅读位置按帖子保存在 `sessionStorage`，关闭标签页即失效；页面结构变化导致页数减少时，恢复位置会夹到最后一页。
- 排序工具栏挂在 `.link-comment` 内，站点清空该节点时会被移除；MutationObserver 在下一帧重建并恢复选中模式。
- 排序读取已渲染的点赞数、相对时间与用户名；“作者”模式按用户名与帖子作者比对，同名用户会一并排到前面。
- CY 屏蔽依赖 `link/tree` 返回的 `is_cy` 字段与楼层的 `data-comment-id`；站点改版去掉字段或属性后，开关仍可点，但不会命中评论。
- 帖子页只为已渲染但未识别的楼层补拉接口，最多 10 页（200 条）；超过上限的楼层保持原样，不误隐藏。
- 帖子页首次识别会额外请求评论接口；未登录或触发风控时请求失败，评论保持可见，需打开帖子或稍后重试。
- 回复编辑器仍由站点原生逻辑管理；沉浸阅读期间它随原生评论区一起隐藏，退出沉浸后回到原来的双栏位置，原生回复、点赞与展开楼中楼都由站点处理。站点原生评论区的“加载更多”由 `#page-bbs-link .link-comment` 的滚动触发，该容器或站点的加载控件结构变化时可能失效，需要重新对齐选择器。
- 沉浸阅读的文章主评论发送 `is_cy: 0`、`reply_id: "-1"` 与 `root_id: "-1"`；楼层回复发送该条评论 ID 与楼层 ID，楼中楼回复同样以所属楼层作为根。发布成功后清除该帖缓存、重置回复目标并重新拉取第一页，同时更新阅读栏计数。真实评论树的 `root_id` / `parent_id` 字段形态，以及回复接口对 `reply_id` / `root_id` 的接受结果仍待确认；未在登录态页面实测回复发布。
- 社区首页隐藏整个右栏；若后续需要保留右栏中的其他模块，需要改为按模块隐藏。
- 社区首页没有找到可确认的未读筛选路由或接口参数：`H` 与“社区首页”按钮只返回 `/app/bbs/home`，是否仅展示未读内容仍由站点信息流决定，待登录真实页面复核。
- 纸页与雾青预设依赖站点现有类名着色，站点改版后可能出现未着色的新容器；深色预设同样按类名覆盖，登录表单始终保留浅色。
- 站点全局 `* { padding: 0; margin: 0; font: ... }` 会覆盖 Shadow DOM 的 `:host` 普通声明，排序栏的 host 样式因此全部加 `!important`；新增 Shadow 组件时需沿用同样写法。
- 站点用 `::before` / `::after` 画卡片底部色带与 1px 分隔线，颜色写死为浅灰；底部色带在所有主题下隐藏，其余分隔线在深色主题逐个覆盖。站点改版新增同类伪元素时需同步补充，否则会再次出现白条。
- 正文内嵌卡片（`com-game-card`、`com-album-card`、`com-award-table-card`、`com-chatroom-card`、`com-league-card`、`com-match-card`、`com-mod-card`、`com-sku-card`、`com-wiki-card`）的底色、描边、文字、药丸底与按钮在站点样式表里写死为浅色，深色主题按这 9 类容器逐组覆盖；站点新增卡片类型时同样会出现未覆盖的浅色块。
- 顶部导航依赖 `.nav .nav-links` 与 `.nav-link` 类名：脚本隐藏原生按钮并插入自己的入口，站点改版换容器后需要同步选择器。隐藏的原生按钮仍留在 DOM 中，站点自己的路由与统计不受影响。
- 导航按地址判断激活项；站点若改用纯前端状态切换而地址不变，激活项可能停在上一页，直到下一次地址变化或导航重建。
- 连读候选来自会话浏览记录、已渲染信息流、连续发现队列与相关推荐：信息流每页 30 条，每次发现最多取 3 页并推进 `offset`；到达站点信息流末尾、队列耗尽或请求失败时，相关推荐仍有未访问项就自动进入，只有没有任何可用候选时才停止并显示可重试提示，不伪造候选。已访问与已见集合按账号隔离，只保留在本次会话，跨标签页或清空 `sessionStorage` 后重新开始。直接打开帖子或刷新后，信息流顺序可能尚未建立，此时先尝试连续发现，相关推荐仅作兜底。登录态下 `/bbs/app/feeds` 的实际返回仍待确认；未登录公开请求返回 HTTP 200 但 `status` 不是 `ok`。
- 连读切换优先调用站点 Vue 路由（`#app.__vue_app__.config.globalProperties.$router`）；取不到 router 时退回站点 `<a>` 点击，会退化为整页跳转，功能仍可用但会刷新。
- 社区内搜索依赖 `/app/topic/link/<topic_id>` 路由与 `.topic-link__main`、`.topic-link__filter-row` 结构；筛选行存在时优先插在它的实际父节点 `.topic-link__panel` 内，筛选行缺失时退回 `.topic-link__main`。站点改版换容器后搜索栏可能不会挂载或位置改变。
- 社区名优先读右栏社区卡 `.topic-aside__topic-indicator`，读不到再退回页头标题与 `document.title`；右栏尚未渲染时占位文案会短暂使用页头名称。
- 社区搜索接口受站点风控影响：未登录或触发验证码时返回非 JSON 或失败状态，面板显示错误，不回退到全站结果；回退请求不带签名，若风控要求签名则仍会失败。

- 社区搜索不持久化关键词、时间筛选与结果，也不实现站点搜索的 `filter_tag` 分类筛选；刷新后回到社区原生信息流。
