# QQ Mail Theme Toggle
为 QQ 邮箱网页版新增一个深浅色主题切换按钮的用户脚本（UserScript）。

- 版本：1.2.4
- 许可：MIT
- 运行环境：ScriptCat / Tampermonkey / Violentmonkey 等 UserScript 管理器
- 适用页面：`https://wx.mail.qq.com/home/*`（`@noframes`）

## 安装
1. 安装用户脚本管理器（ScriptCat 推荐）。
2. 点击安装入口直接安装（推荐，可自动更新）：[QQ Mail Theme Toggle](https://ghfast.top/https://raw.githubusercontent.com/CYoJkoY/Yoko-ScriptCat-Scripts/release/qq-mail-theme-toggle.user.js)。
3. 或在管理器中新建脚本、粘贴脚本完整内容后保存。
4. 打开 QQ 邮箱网页版；左下角会出现一个 36×36 的圆形主题按钮。

## 核心特性
- 脚本图标以 QQ 邮箱官方图标为底稿：保留白色圆盘、黄/绿/红三色叶片与蓝色企鹅，整体放进深色圆角底板，右下角叠加月亮徽章表示主题切换；轮廓由官方 96×96 图标逐色追踪而来，不是另画的相似图形。
- 在页面左下角注入固定定位的圆形图标按钮：浅色时显示月亮，深色时显示太阳，图标表示“点击后的下一个主题”。
- 深色主题**不反色**。脚本只替换 QQ 邮箱界面使用的设计令牌（背景、文字、边框、阴影等 CSS 变量），并重新映射邮件列表、侧边栏、顶栏和弹层中的少量组件颜色。
- 邮件正文是第三方 HTML，颜色写死在内联 `style` 里，无法靠令牌覆盖。脚本在深色模式下逐个元素重映射这些颜色：纸白底色变深、深色文字提亮、浅色边框变深、饱和度足够的高亮色保留色相，既不使用 `filter` 也不做反色。
- 写信编辑器中的内联黑字、粘贴内容的浅色底纸也会按对比度适配；调整通过独立样式表显示，不改写待发送正文的 HTML、字体颜色或背景属性。光标、引用边框和待办框同步使用深色配色。
- `img`、`video`、`picture`、`canvas`、`svg`、`iframe` 等媒体元素及其子树被整棵跳过，图片、图表、二维码和视频保持原始像素。承载文字的 CSS 背景图或渐变会增加深色遮罩，再重新计算字色；不含文字的装饰背景图保留原样。
- 从未手动选择过主题时跟随系统 `prefers-color-scheme`；点击按钮后模式写入 `GM_getValue` / `GM_setValue`（无授权时退回页面 `localStorage`），刷新后仍然生效；系统主题变化只在用户未手动选择时生效。
- `MutationObserver` 会在 QQ 邮箱重绘 DOM 后把按钮重新挂载；按钮自身使用两套独立配色，深浅主题下都保持可读，并保留键盘焦点、Enter/Space 与 `aria-pressed` 语义。
- `@run-at document-start`：主题属性和样式表在首帧渲染前注入，避免整页浅色闪烁。
- 深色外壳的灰阶前景使用更高亮度和不透明度；邮件列表预览行、空状态文案与外壳图标（依赖 `currentColor` 的 SVG）会继承这套浅色前景，避免在深色背景上发灰或发暗。
- 空白阅读区（`.mail-list-page-reader-tips .empty-tips::before`）的邮箱插画原本是一张深色 `background-image`（`#182B40`、约 30% 不透明度），在深色底上几乎不可见；脚本改用同形状、同尺寸（160×120）的内联 data URI 插画，以浅色前景重绘。这是插画替换，不是滤镜，也不是反色，且不涉及邮件正文媒体像素。
- 邮件摘要、空状态提示、账号邮箱和搜索占位符提高亮度，备注摘要仍以黄色区分。
- 滚动条滑块、未选中复选框和灰色加载图标使用浅色前景；加载图标保留原有渐变与动画。

## 主题原理
QQ 邮箱的界面由 `<body class="page-color-theme">` 上的一组 `--base_white_*`、`--base_gray_*`、`--bg_*` 等设计令牌驱动。深色模式在 `<html data-yoko-qq-mail-theme="dark">` 下重新声明这些令牌：原本的“白色层”变成深色背景，原本的“灰色文字”变成浅色文字；同时对少量直接写死颜色的组件做定向覆盖。规则统一带 `body` 前缀，以稳定压过 QQ 邮箱自身的 `body.page-color-theme` 选择器。

邮件阅读区（`.mail-detail-content`）在深色模式下只被指定为深色画布（`color-scheme: dark`、深色背景与浅色前景）。真正的邮件 HTML 由 `core/emailDark.ts` 逐元素处理：

- 遍历 `.mail-detail-content` 子树，读取每个元素的**计算样式**，因此内联样式、邮件自带 `<style>` 和继承颜色都能覆盖到。
- 先读取整棵正文的计算样式，再写入新颜色，避免父元素先被提亮后，背景图区域的文字错误继承浅色。亮度 ≥ 0.18 的底色（包括浅灰纸张）替换为 `#1A2028`；带色相的底色保留色相并压暗。半透明底色与实际祖先背景合成后，再计算文字对比度。
- 文字与 `-webkit-text-fill-color` 在有效背景上的对比度不足 4.5:1 时重新配色：优先使用 `#E8ECF1` 或保留色相的浅色；候选色仍不够清楚时选择满足对比度的白色或黑色。低透明度文字需要改色时使用不透明前景，完全透明的文字仍保持透明。亮度 ≥ 0.55 的细边框替换为 `#3A4049`。
- 所有改动以 `!important` 写回内联样式，同时记录原始值、优先级与脚本写入值；切回浅色时逐条还原。若页面后来更新了同一属性，则保留页面的新值。
- 媒体元素直接跳过。有文字的背景图及渐变在原图层前增加 85% 不透明度的深色遮罩，原图层的尺寸、定位、重复、混合方式等配置同步保留。按原图最亮为纯白估算遮罩后的背景上界，再判断文字对比度；内部另有底色的容器继续独立计算。切回浅色时遮罩和图层配置一并还原。

写信区（`.xmail-cmp-editor-content[contenteditable="true"]`）复用同一套颜色计算，但不写回正文节点。脚本在编辑器外创建带深色主题条件的样式表，通过节点位置选择器显示配色；输入、粘贴、调整文字样式后重新计算。切回浅色或卸载时移除该样式表，编辑器的 HTML 始终保留作者配色。若粘贴内容的内联 `!important` 底色无法由样式表覆盖，则按保留的实际底色选择可读字色。

浅色模式只是移除根节点上的主题属性，所有深色规则立即失效，页面回到 QQ 邮箱原生配色。

## 与 QQ 邮箱的兼容
- 追加界面 `<style>`、写信区显示配色所需的独立 `<style>`、一个原生 `<button>` 和根节点属性，不改动 QQ 邮箱的 DOM 结构、类名或事件处理器；卸载后全部移除。
- 主题规则只作用于界面令牌和明确的组件选择器；邮件正文的改色只写内联属性，并记录原值以便完整还原，不对 `img`、`video`、`canvas` 应用 `filter` 或 `mix-blend-mode`。
- `MutationObserver` 关注阅读区和写信编辑器内的新增节点、文本及 `style`、`class`、`color`、`bgcolor`、`background` 变化，并使用一次性的定时器合并多次变更。重新配色时暂停自身观察，避免内联写入反复触发扫描；节点移动后也会依据新背景重新处理。
- 已知限制：若某封邮件的正文被跨域 iframe 承载，脚本无法进入该文档，此部分仍显示原始浅色；纯图片邮件（整封只有一个 `<img>`）不会被改色，图片照常显示。
- 已知限制：阅读区外的样式表单独发生变化、却没有引起正文 DOM 或上述属性变化时，不会主动重新扫描；重新打开邮件即可重新处理。
- 已知限制：保留原本的深色底和近黑边框，因此“浅底 + 近黑边框”的邮件在深色画布上分隔线可能不明显。脚本不分析背景图片像素，而是给承载文字的背景统一加遮罩，因此这类背景图在深色模式下会变暗。
- QQ 邮箱重绘或路由切换导致按钮被移除时，观察器会自动补回，不会重复插入。
- 若 QQ 邮箱后续调整令牌命名，深色模式可能局部回退为原生浅色，但不会破坏邮件内容或图片颜色。
