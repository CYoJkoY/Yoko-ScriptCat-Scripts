# AI Chat Turbo Engine

面向长对话与重度使用的跨平台 AI 聊天增强用户脚本。在受支持的 AI 对话页面上叠加一层轻量增强，解决四类实际痛点：长会话渲染变卡、超长代码块挤占阅读空间、大段文本撑爆输入框、上下文难以迁移到新会话。

当前版本：**0.20.7**
许可证：**MIT**
运行方式：单文件用户脚本，无外部依赖，无网络请求，不申请任何 GM 权限。

---

## 特性一览

- **常驻统计 HUD**：48 × 48 紧凑负载仪表显示消息总数，圆环比例与整卡颜色表达提醒上限；拖到屏幕边缘即收成侧边信息条，打开面板时为同侧抽屉
- **视口脱水**：对超过保留轮次的旧消息冻结渲染，降低长对话开销；空白占位区点一下即可恢复该轮
- **侧边栏悬停探出**：ChatGPT / Perplexity / Qwen / 智谱清言 / Z.ai / Gemini 的折叠导航栏在指针停留后原地展开，聊天列位置不动；移开即收回
- **长代码折叠**：超过阈值的助手代码块自动折叠，保留语言、行数与一键复制
- **长文本伪文件**：键入或粘贴超长文本时转为悬浮托盘中的"虚拟文件"，发送时合并附加；输入框文本与文件可随时互相转换，已发送消息里的伪文件也能在胶囊与原文之间切换
- **发送鲁棒性**：多级发送按钮查找 + pointer 序列模拟 + form 兜底提交
- **推理强度记忆**：自动记住每个平台上次使用的思考开关 / 推理强度，新对话与刷新后静默还原
- **元宝工具记忆**：记住腾讯元宝工具行里选中的专业写作、AI 生图等原子工具，刷新或输入框重建后自动恢复
- **一键交接**：单按钮完成"生成交接包 → 打开新对话 → 填入恢复指令"，任一步失败自动把进度复制到剪贴板
- **会话历史检索**：当前会话全文检索，命中后定位并高亮
- **原始上下文导出**：把整段对话提取为 Markdown 复制到剪贴板

## 安装

前置条件：Chrome / Edge / Firefox / Safari + 任一用户脚本管理器（Tampermonkey、Violentmonkey、Greasemonkey）。

1. 安装用户脚本管理器（ScriptCat 推荐）。
2. 点击安装入口直接安装（推荐，可自动更新）：[AI Chat Turbo Engine](https://ghfast.top/https://raw.githubusercontent.com/CYoJkoY/Yoko-ScriptCat-Scripts/main/dist/ai-chat-turbo-engine.user.js)。
3. 或在管理器中新建脚本、粘贴脚本完整内容后保存。
4. 打开受支持的对话页面，右下角出现紧凑的 `Turbo` 负载仪表即表示生效。

脚本以 `@run-at document-start` 注入，`@noframes`，`@grant none`。头部声明了 `@updateURL`（jsDelivr）与 `@downloadURL`（ghfast 代理），不依赖在部分网络下会超时的 `raw.githubusercontent.com`；从没有这两个字段的旧版本升级需重装一次，详见仓库 README。

## 功能详解

### 常驻统计 HUD

悬浮仪表默认位于右下角，可拖拽，位置保存在 `localStorage`。整体为 **48 × 48** 的圆角方形，内部是 40px 负载环，环中只显示当前消息总数；负载上限改由圆环占用比例、整卡颜色、悬停提示与 `aria-label` 表达，避免 `999/999` 这类长文本挤在 40px 环内。

- 负载低于提醒上限的 **70%**：青色常态。
- 达到 **70%**：整个控件切换为琥珀色，包括底色、边框、负载环、数字与悬停阴影。
- 达到 **100%**：整个控件切换为玫红色，提示已达到提醒上限。
- 悬停提示只保留当前负载摘要与打开方式；完整指标保留在 `aria-label` 和主面板顶部的四项状态卡中。
- 状态卡依次显示消息总数、已脱水、代码折叠、虚拟文件。消息数达到上限的 70% 或 100% 时，状态区出现可操作的提示，可直接跳到检索框或提醒上限输入框，不再只靠红色数字表达状态。

提醒上限可在面板的「消息提醒上限」数值框中调整，范围 **10 至 999**，默认 **60**，修改后立即保存并刷新仪表。**该阈值仅为消息数量启发式，不代表模型真实上下文容量、智力或回答质量；它只统计检测到的消息条数。**

| 指标 | 含义 |
| --- | --- |
| 消息 | 当前会话检测到的消息条数（同时作为负载分子的来源） |
| 脱水 | 已被冻结渲染的消息数 |
| 折叠 | 已被折叠的代码块数 |
| 文件 | 待随下一条消息发送的虚拟文件数 |

点击悬浮仪表（或按 `Alt + T`）打开主面板。面板宽度为 `min(420px, calc(100vw - 24px))`，高度上限为 `min(720px, calc(100dvh - 24px))`，内容超出时面板内部滚动（`overflow-y: auto` + `overscroll-behavior: contain`），矮屏与窄屏上都不会被截断。

悬浮仪表拖到距左右屏幕边缘 **26px** 以内松手即贴边，收成 **30 × 86** 的侧边条：横向占位从 48px 缩到 30px，环、数字与新增的 "AI" 标记一起挤进窄条。贴边后再次拖动从贴边位置接续；`pointercancel` 回到贴边位，窗口或 `visualViewport` 尺寸变化后重新贴齐。标题栏的「贴边 / 取消贴边」按钮可以直接切换，状态保存在 `ai_turbo_hud_dock`（`left` / `right`），刷新后恢复。贴边状态下打开面板，面板从同一侧滑入，成为占满视口高度的侧边抽屉，宽度 `min(392px, 100vw)`；取消贴边回到居中的悬浮面板，`prefers-reduced-motion` 下不播放滑入动画。

面板首屏依次展示标题栏、四项状态卡、负载提醒、历史检索、上下文交接和常用开关；活跃保留轮次、消息提醒上限、界面主题与「恢复默认设置」收进默认关闭的「高级设置」。主题支持自动、浅色、深色三种模式：自动模式先读取宿主根节点的暗色类名、主题属性与 `color-scheme`，再以背景亮度和 `prefers-color-scheme` 兜底；手动选择直接覆盖宿主判断。宿主主题属性或系统配色变化时，悬浮仪表与面板同步切换。

### 视口脱水（Adaptive Dehydration）

对超出保留轮次的旧消息追加 `.ai-turbo-dehydrated`，实现方式：

```css
content-visibility: hidden;
contain: layout paint style;
contain-intrinsic-size: auto var(--turbo-cached-h, 120px);
```

占位区本身是可点击的：鼠标悬停会显示虚线描边与斜纹底纹表示“此处有一轮被冻结的消息”，点击即恢复该轮的真实渲染，并记入 `restoredTurns`（`WeakSet`），后续同步不会再把它冻回去（页面重载后重新计算）。

设计取舍：

- 相比 `display: none`，`content-visibility: hidden` 保留节点的 `textContent` 可读性，因此历史检索、上下文导出、交接包提取仍能覆盖全部消息。
- 冻结消息内的按钮与链接不可点击，这是有意的取舍。点击空白占位区，或命中历史检索跳转，即可恢复该轮。
- `contain-intrinsic-size` 用折叠前缓存的高度占位，避免滚动条抖动。

保留轮次可在面板中调整，范围 **2 至 50**，默认 **8**。

### 侧边栏悬停探出

平台把侧边栏收成几十像素宽的图标条后，想看完整标签就得点一次原生开关，而原生展开会带着整列聊天内容重排，动画期间每一步布局都要重算。引擎改为在指针停留 **70ms** 后让这条图标条原地加宽到该站点的展开宽度，移开 **160ms** 宽限后收回。触发区不是导轨自己的盒子：从视口边缘直通导轨远侧的一条接近带（至少 **28px** 宽，两侧再各放宽 **10px** 容差）同样算作「指针想展开导航」。

已实测并在 `PLATFORMS` 中声明 `sidebar` 的站点：

| 平台 | 折叠宽度 | 探出宽度 | 探出时需要恢复的折叠内容 |
| :--- | ---: | ---: | :--- |
| ChatGPT | 52px | 340px | 面板透明度、`#app-shell-sidebar` 等内层 shell 的宽度，以及带内联隐藏声明的滚动区 |
| Perplexity | 56px | 240px | 间距容器内被裁到折叠宽度的 `nav` |
| Qwen | 60px | 240px | 会话列表各级容器的 `visibility` 与标题 |
| 智谱清言 | 40px | 260px | 条目宽度与 `.subject-text` |
| Z.ai | 60px | 238px | 内层 shell 宽度、标签 `max-width` / 模糊、滚动区透明度 |
| Gemini | 52px | 248px | `bard-sidenav`、`infinite-scroller`、`mat-nav-list` 等内部 shell 的宽度与标签 |
| Microsoft Copilot | 48px | 256px | 站点层内的轨道宽度变量、抽屉 body 宽度、条目 `max-width` 与标签 `display` |

- **不销毁也不复制原生节点。** 探出只是给侧边栏节点写上 data-ai-turbo-sidebar-peek 属性并写入两个自定义属性，站点自己的监听器、滚动位置与会话列表都保持原样。相比「销毁折叠栏、按需新建完整侧栏」，这里不产生任何新节点，也不需要在收回时重新请求或重建内容，内存与首帧开销都更低。
- **聊天列零重排。** 直接加宽会让聊天列被挤窄（Gemini 实测 1604px 缩到 1408px）。引擎按折叠宽度算出增长量，写成负外边距（自定义属性 --ai-turbo-sidebar-peek-shift）抵消，聊天列宽度与左边界保持不变，侧栏以 z-index: 5 覆盖在聊天列之上。位移在 flex / grid 行以及宽度跟随子级的 block 容器上自动测量；父容器裁切溢出时改用该平台声明的固定 `shift`（Z.ai 为 -178px）。
- **只恢复被折叠隐藏的标签。** 每站差异收进带探出属性作用域的 CSS：Gemini 恢复 `infinite-scroller` 与 `mat-nav-list`，Qwen 恢复会话列表的 `visibility`，智谱清言恢复 `.subject-text`，Z.ai 恢复标签宽度与透明度，Perplexity 恢复 `nav` 宽度；这些规则在收回时随之失效，不残留。
- **脚本只碰必要的内联值。** ChatGPT 的展开面板常驻 DOM，但滚动区带内联的隐藏声明，样式表压不过它，因此探出模块按快照临时抬起该声明、收回时原样写回；这是唯一需要改内联样式的情况，同样不复制节点。
- **内容不再被内层容器裁掉。** 有些站点把面板内容挂在按折叠宽度写死的容器上，只加宽导轨会出现「导轨变宽了、标签仍被裁」的半截状态。平台在 `sidebar.shells` 里列出这些容器（ChatGPT 的 `#app-shell-sidebar`、Gemini 的 `bard-sidenav` 等），探出时同时给 `width` / `min-width` / `max-width` 写探出宽度，收回时按内联快照逐条还原；基础规则也带 `min-width`、`max-width` 与 `box-sizing: border-box`，避免站点自己的 `max-width` 把加宽压回去。
- **中间空隙不会打断探出。** 面板内容可能画在导轨之外的兄弟层里，指针经过这些空白区域时 `elementFromPoint` 命中的是空白、透明遮罩或别的节点。探出期间改用几何包含判断：导轨自身加宽后的矩形，加上所有被拉伸的 shell 矩形，指针落在其中任一处都算仍在面板上；真正离开这条带才进入 160ms 的收回宽限。
- **导航后立刻退场。** 点击探出面板里的历史条目会由站点自己换路由并重建导航，此时再点一次原生折叠按钮，会命中新路由下的另一个控件，并与页面自己的过渡抢时序，表现就是收回极慢。探出在点击捕获阶段就撤销，且记录「打开时按下的是哪个原生控件」，路由或文档变化后不再按下它；`popstate` / `hashchange`、导轨被替换、`location.href` 与打开时不一致，都走同一条无动画退场路径。
- **状态以站点为准。** 站点自己展开侧栏、节点被替换、或者按下原生开关时，探出属性立即撤销；在原生开关上按 Enter / 空格、Esc、在侧栏外按下指针也会立即收回。触屏与手写笔指针不触发。
- **其余平台默认关闭。** 只有 PLATFORMS 中声明了 sidebar 的平台启用，未声明的平台不注册任何监听。豆包与元宝用 transform 把侧栏整体移出容器，千问折叠后导航节点直接消失，纯 CSS 加宽不可行；DeepSeek / Grok / Poe 当前没有可复现的折叠侧栏 DOM，暂不声明。
- **Claude 不再适配。** 本轮移除 Claude 的平台定义、域名识别与 `@match`，引擎不再在 claude.ai 注入，也不加载任何平台配置。

### 长代码折叠

助手代码块高度超过 **300px** 时自动折叠为 **200px** 预览高度，并在上方插入一条工具栏：

- **语言标签**：从 `language-*` 类名、`data-language` / `lang` 属性，或原生头部装饰中识别
- **行数统计**：基于实时文本计算
- **展开 / 收起**按钮
- **一键复制**：把整段代码（而非预览部分）写入剪贴板，按后按钮即时反馈「已复制」/「复制失败」，1.2s 后词回「复制」；剪贴板 API 不可用时反馈「不可用」

输出中的代码块会显示流式状态徽标；若 1500ms 内内容无变化，则自动切换为静态行数。

ChatGPT 的代码卡片结构较特殊，脚本会向上最多追溯 10 层祖先以定位真正的外层代码卡片容器，并以 `data-turn-key`、`article[data-turn]`、`li[data-message-role]` 等作为硬边界，避免把整条助手消息当作折叠目标。**无法安全识别边界时放弃折叠并恢复原样。**

### 长文本伪文件

输入框文本达到 **1500 字符**时触发，粘贴与手动键入走同一条判定。

处理流程：

1. 粘贴时拦截原生事件，文本不写入输入框；键入时到达阈值后，在输入框上方出现托盘并提示「输入框里有长文本」。
2. 在输入框上方生成悬浮托盘，列出已捕获的虚拟文件；文件名为 `pasted_text_{KB}kb.txt`。
3. 发送时把虚拟文件与输入框内容合并为一条消息，用 `[[TURBO_VFILE_START:...|行数|字节数:TURBO_VFILE_END]]` token 包裹文件内容。
4. 消息回显后，脚本检测到 token 即把大段文本折叠为小胶囊，胶囊作为消息气泡的**兄弟节点**插入（不侵入平台自身 DOM 结构），原始提问文本若在胶囊外则单独保留。

托盘头部提供「文本转文件」：把输入框里的长文本收进一个 `composer_text_{KB}kb.txt` 并清空输入框；每个文件条目提供「转文本」：把正文放回输入框（已有其他文字时空一行追加）并移除该文件。正文始终原样保留，两个方向可以反复往返，不会因为转换丢失换行或截断内容。

每个虚拟文件条目提供：

- **查看**：独立预览窗口，首屏渲染前 12,000 字符，超出部分按「显示全部」再排版；底部「复制全部」写入完整正文（发送时提交完整全文）
- **转文本**：把该文件的正文放回输入框作为普通消息，并移除文件条目
- **删除**：从托盘移除

#### 已发送消息里的胶囊

历史里的每条胶囊都是一个 `<button>`，点它不会展开气泡里的原始文本，而是由引擎在自己的预览窗口里显示正文：

- **按 token 解析，不认平台 DOM。** 一条消息的正文从 `textContent` 里按 `[[TURBO_VFILE_START:...]]` 标记切片，宿主把围栏渲染成 `<pre>`、高亮 span 还是纯文本都不影响识别；正文本身含有围栏也不会被截断。所有平台共用同一条解析路径，没有站点特判。
- **一条消息里的多个文件各成胶囊。** 每个 token 单独解析，胶囊按顺序排列；点第几个就显示第几个文件。
- **预览窗口由引擎自建。** 窗口挂在 `document.body` 上，按视口定位，不受宿主气泡的 `overflow`、裁切或重建影响；`Esc`、点背景、关闭按钮都能关掉，焦点在窗口内循环并在关闭后回到原位置。
- **折叠不创建新内容。** 原始大段文本只是被隐藏（`display` + `contain` 行内声明），不复制节点，也不参与排版；提问文本若随整块被隐藏，会在胶囊上方补回一行可见原文。
- **文件与原文自由切换。** 每轮文件栈末尾有「展开原文 / 收起为文件」：展开时抬升同一批容器的行内隐藏声明、隐藏补回的提问行，原消息按宿主自己的排版显示；收起时恢复原状。切换只改行内样式，不重建消息节点，宿主的监听与选中状态都不受影响。
- **随轮次一起收起。** 平台把该轮脱水成占位条时，胶囊行同步隐藏，恢复后重新出现；平台重绘消息时按挂载状态修复，宿主消失就移除孤立胶囊。
- **正文随时重读。** 点开胶囊时从当前页面重新切一遍正文，平台已卸载该轮内容时预览会提示「正文已不在页面中，重新打开这段对话后再试」。

#### 输入框变形下的托盘定位

平台原生附件预览插在输入框上方时，会撑高 composer 并上移输入框。为了让伪文件托盘贴合包含原生附件在内的整体视觉上缘，脚本做了以下处理：

- **`getInputContainer`**：从候选容器中挑选"完整包裹输入框且面积最小"的那一个，避免把整页 wrapper 误判为 composer。
- **`getComposerVisualBounds`**：从 anchor 起向上最多追溯 5 层父节点，将紧贴上方（垂直间隙 ≤ 48px）、水平方向与当前区域重叠 ≥ 35% 的兄弟节点（原生附件预览、工具条、按钮行）并入视觉边界。
- **视觉边界过滤（0.13.8）**：在把兄弟节点并入边界之前，先剔除以下类型，避免误把悬浮控件或过度外扩的容器当作 composer 的一部分：
  - `position: fixed / sticky` 的元素（如"跳回输入框"等悬浮按钮）
  - 不含输入类子节点的单独 `button` / `[role="button"]`
  - 顶部已滚出视口上方（`rect.top < 8`）的节点，命中后立即终止向上扩展
  - 高度超过 `max(baseRect.height * 3, 320px)` 的巨型容器（通常代表整段对话容器）
- **rAF 持续追踪循环**：以 90ms 间隔调用位置更新，捕捉 `ResizeObserver` 无法感知的纯平移。循环仅在存在虚拟文件时运行。
- **位置签名去重**：每帧计算 `left|bottom|width|maxHeight` 组合签名，未变化时不写样式，避免打断 CSS 过渡。
- **输入框引用缓存**：仅在失效时才走完整 `getChatInput()`，避免每帧全量查询。
- **`ResizeObserver` 扩展**：同时观察输入框、anchor、以及向上 5 层的祖先及其父节点，覆盖"祖先 wrapper 被附件撑高"的场景。
- **`visualTop` 钳制（0.13.8）**：在 `positionVirtualFileTray` 中，对最终计算出的 `visualTop` 做上下限夹取：
  - 上界：`min(visualTop, inputRect.top)`，绝不高于输入框顶部
  - 下界：`max(viewportPadding + verticalGap + 60, …)`，确保托盘不会因视觉边界异常而跑出视口

  这一层钳制用于兜底，即使 `getComposerVisualBounds` 因为某些未知结构算出了异常值，托盘位置仍保持在视口内。

### 发送按钮查找与触发

完整的"发送意图识别 → 按钮查找 → 事件模拟 → 兜底提交"链路，解决平台改版或按钮不在预期位置时消息发不出去的问题。

#### 多级查找 `findSendControl`

按以下顺序尝试，命中即返回：

1. **平台选择器**：当前平台 `sendButtonSelectors` 中任一选择器命中的可用按钮（且与输入框共享 composer 容器）。
2. **输入框所在 `form`**：先找 `button[type="submit"]` 与非 `type="button"` 的按钮，再在所有按钮中按 `isSendLikeButton` 过滤。
3. **composer 容器**：在 `[data-chatgpt-composer]`、`.input-area-container`、`[class*='composer']`、`[class*='input-area']`、`[class*='input-container']`、`[class*='query-bar']`、`rich-textarea`、`fieldset` 中按 `isSendLikeButton` 查找。
4. **向上 8 层**：从输入框向上遍历最多 8 层祖先，按 `isSendLikeButton` 查找。

`isSendLikeButton` 基于 `aria-label` / `title` / `data-testid` / `data-tooltip` 判断，命中 `send`、`submit`、`发送`、`提交`、`prompt`、`ask`；显式排除 `stop`、`停止`、`cancel`、`abort`、`中止`、`取消`，避免 AI 生成中误触停止按钮。

`isButtonUsable` 还会过滤掉隐藏、零尺寸、以及挂在脚本自身 UI 内的按钮。

#### 事件模拟 `triggerSendButton`

现代前端框架的发送按钮多绑定 `onPointerDown` / `onMouseDown`，直接 `btn.click()` 往往无效。`triggerSendButton` 依次派发：

```
pointerdown → mousedown → pointerup → mouseup → click
```

并携带 `bubbles: true, cancelable: true, view: window, button: 0, pointerId: 1, pointerType: "mouse", isPrimary: true`，确保 React 与 Pointer Events 监听都能识别为一次真实点击。

#### 重试与兜底 `sendWithRetry`

以 50ms 间隔最多轮询 **40 次（约 2 秒）**：

1. **前 15 次（约 750ms）**：只接受**可用且未 disabled** 的发送按钮。
2. **第 16 次起（约 800ms）**：允许命中的按钮处于 `disabled` 或 `aria-disabled="true"`，此时脚本会先 `removeAttribute("disabled")` 并置 `aria-disabled="false"`，再调用 `triggerSendButton`。
3. **第 40 次兜底 `fallbackKeyboardSubmit`**：先尝试 `form.requestSubmit()`；若无 form 或该方法不可用，则派发带 `keyCode / which = 13` 的 `keydown` + `keyup` Enter 事件。

#### 发送拦截 `handleSendIntercept`

- **Enter 键**：存在虚拟文件且未处于提交中时，拦截 `Enter`（不含 `Shift`、非输入法组合状态），合并虚拟文件并触发 `sendWithRetry`。
- **点击**：判断用户是否点击了"发送按钮"时，**不再强制依赖 `isSendControlForInput`**，而是：
  1. 先用 `currentPlatform.sendButtonSelectors` 做 `closest()` 匹配；
  2. 未命中时向上最多 4 层，按 `isSendLikeButton` 兜底识别。

  命中即视为发送意图，`preventDefault + stopPropagation` 后合并虚拟文件并触发 `sendWithRetry`。

### 一键交接

把当前对话的工作状态迁移到新会话或新模型，避免从零复述。

#### 面板按钮

0.13.8 起，交接区从原来的四个按钮（发送指令 / 恢复到新对话 / 仅复制 YAML / 仅复制恢复指令）合并为**一个**：

| 按钮 | 行为 |
| --- | --- |
| 一键交接（生成并恢复） | 见下节流程 |
| 复制原始上下文（回退） | 直接把整段对话导出为 Markdown 到剪贴板 |

#### 一键交接流程

`startOneClickHandoff` 内部按优先级处理：

1. **最新助手回答中已存在完整交接包** → 直接进入 `proceedOneClickHandoff`：构建恢复指令 → 通过 `sessionStorage` 跨页暂存 → 点击新对话入口 → `resumePendingHandoffPrompt` 在新页面填入。
2. **尚无交接包** → 构建生成指令并写入输入框：
   - 输入框不存在 → 把生成指令复制到剪贴板并提示。
   - 输入框已有草稿 → **不覆盖**，把生成指令复制到剪贴板并提示。
   - 写入后 → `sendWithRetry` 发送：
     - 发送未确认 → 把生成指令复制到剪贴板并提示。
     - 发送成功 → 进入 `waitForHandoffPackage` 轮询。

#### 等待交接包

`waitForHandoffPackage` 以 600ms 间隔轮询，超时阈值 **3 分钟**：

- 轮询尚未出现助手消息（`turns.length <= baselineTurns`）时不误判；
- 一旦 `extractLatestHandoffText` 命中 → 关闭轮询并进入 `proceedOneClickHandoff`；
- 超时仍未命中 → 把生成指令复制到剪贴板并提示。

#### 失败即回退

以上所有异常分支都统一走 `copyHandoffFallback(text, statusMessage, alertMessage)`：

- 优先调用 `navigator.clipboard.writeText` 写入进度文本；
- 状态栏同步显示失败原因（`handoff-status`）；
- 剪贴板不可用时在状态栏追加提示并弹窗要求手动复制。

**"当前进度"** 的含义：

- 发送阶段失败 → 复制的是**生成指令**（`buildHandoffGenerationPrompt`）；
- 恢复阶段失败 → 复制的是**恢复指令**（`buildHandoffRestorePrompt`，即"交接包 + 前置要求" 完整模板）。

这样即使自动化全程中断，用户仍能从剪贴板直接粘贴接续。

#### 交接包格式

交接包实际是**纯文本结构化格式**（非严格 YAML），要求模型直接输出、不使用 Markdown 代码块，从 `[META]` 到 `[END]`、字段固定、每字段形如 `字段名: 内容`：

```
[META]            version / generated_at / source_model / language
[TASK]            objective / success_criteria / current_status
[DECISIONS]       confirmed / rejected / assumptions
[PROGRESS]        done / in_progress / next_actions
[ROLE]            persona / tone / response_format / boundaries
[CONTEXT]         tools / tech_stack / files / data / constraints
[OPEN_ISSUES]     questions / risks / blockers
[KEY_ENTITIES]    people / projects / terms
[HANDOFF_NOTES]   自由补充
[END]
```

提取逻辑优先兼容旧版 YAML 格式（`meta:` 等顶层键），两种格式都会按纯文本处理，不依赖严格 YAML 解析。

#### 恢复指令模板

`buildHandoffRestorePrompt` 要求模型：

1. 直接读取全部字段（按纯文本处理，不必解析为代码）；
2. 输出简短摘要（目标 / 状态 / 决策 / 排除方案 / 下一步 / 角色）；
3. 直接进入角色执行 `next_actions` 首项；
4. 若 `questions` 非空，先按优先级列出并询问；
5. 字段值为「无」或空时跳过。

#### 边界处理

- 新对话输入框已有草稿时，**不覆盖**，改为复制到剪贴板并提示手动粘贴。
- 无法识别新建对话入口或无法暂存 `sessionStorage` 时，同样回退为复制到剪贴板。
- `sessionStorage` 暂存超过 5 分钟自动失效；新对话页面识别不到输入框时也会回退为复制。

### 推理强度记忆

各平台的"深度思考 / 推理强度"是会话级状态，刷新或新建对话后常常回到默认值。脚本把它变成跨会话记忆。记录分两种形态，存进 `localStorage` 的 `ai_turbo_reasoning_memory`。Gemini 带账号槽位的路径（`/u/0`、`/u/1` 等）按 `hostname#uN` 分开存放，其余页面按主机名存放；读取时若当前账号还没有记录，会回退到旧版的主机名记录。

腾讯元宝的模型选择由两个独立维度组成：模型（`Hy4 preview`、`Hy3`、`DeepSeek`）与模式（`快速回答`、`深度思考`、`专家模式`）。这两个维度存在 `localStorage` 的 `ai_turbo_yuanbao_selection`，结构为 `{ model?, mode?, ts? }`，按当前会话作用域存放并保留主机名读取回退；只改变其中一个维度时，另一个维度的记录保持不变。旧版把选项写进 `ai_turbo_reasoning_memory` 的元宝记录会在首次还原时迁移过来：模型文案归入 `model`，模式文案归入 `mode`，并补上当前模式下读到的另一维度。

- `{ mode: "toggle", label, on }`：开关型控件（`深度思考`、`Thinking` 等）。
- `{ mode: "choice", key, controlLabel, path, option, hint, resultLabel }`：选择型控件（Gemini 的模型 / 思考强度、ChatGPT 的推理等级）。`key` 优先取 `data-test-id` / `data-testid` / `id`，最后才用 `aria-label`；`path` 是从触发器到目标行经过的可见子菜单标题（如 `["Thinking level"]` 或 `["思考等级"]`）；`option` 是目标行的标题；`hint` 是同一行的说明；`controlLabel` 是点击前的可见文案；`resultLabel` 是选完后触发器上出现的文案。不记录任何固定等级词表。

控件文案优先读可见的 `innerText`。Gemini 触发器的 `aria-label` 是一整句 `Open mode picker, currently Flash High`，不能当作选项值；可见文案才是实际值。选项行优先取行内可见的 `.label` 与 `.sublabel`，因此即使中文菜单把标题和说明挤进同一行 `innerText`（如 `中 深度适中`），仍会分别记录 `中` 和 `深度适中`；没有这两个结构类时，才退回首行与第二行文案。

1. **录制**：两种途径写同一种记录。
   - 文案变化：点击带弹层语义的控件后，在 400 / 900 / 1600 / 2600ms 读控件文案，变了就把新文案记为 `option`。弹层语义包括 `aria-expanded` / `aria-haspopup`，以及 Angular Material / CDK 系的 `gemmenutrigger` / `cdkoverlayorigin` / `data-state` / `.mat-mdc-menu-trigger`（Gemini 的模型选择器就只有后者）。
   - 选项配对：点击控件后 20 秒内点中选项行，把该行标题、说明以及由可见 `aria-controls` 父行组成的 `path` 与刚才的控件配对。选中态既认 `aria-checked` / `aria-selected` / `data-state` / `role=menuitemradio`，也认 `.selected` / `.checked`、本地化的“已选中”标签和勾选图标；带 `aria-haspopup` 的父行不会被当成选项。带关键词的开关控件（`深度思考` 等）另走 `toggle` 记录。
2. **还原**：页面加载与 SPA 路由变化后，以 500ms 间隔最多轮询 120 次（约 60 秒）等待控件渲染完成，然后按 `key` → 旧文案（可前缀匹配）→ 最像推理/模型选择的控件依次定位：
   - 开关型：状态与记录不一致时用原生 `click` 纠正一次，随后在 100ms × 8 次的窗口里确认状态落定；同一会话内同一控件、同一目标状态只纠正一次。触发器的 `data-state="open" / "closed"` 只代表弹层开合，不参与开关值判断；`aria-expanded` / `aria-haspopup` 命中的弹层触发器也不按开关记录。
   - 选择型：控件文案已经是 `option` 或 `resultLabel` 就不动；否则打开弹层，沿 `path` 中每个可见父行的 `aria-controls` 逐层展开，在当前层按行标题精确找叶子行，点完会重新打开菜单确认选中标记。确认成功后关闭弹层；失败同样关闭弹层。关闭时先派发 `Escape`；若该触发器的 `aria-expanded` 仍为 `true`（元宝的思考模式弹层不处理 `Escape`），再点击同一个触发器，最多 3 次。同一会话内同一条记录最多尝试 2 次，避免菜单反复开合；SPA 路由变化会重置尝试计数。没有 `path` 的旧记录继续走原来的逐词文案回退。
   - 兼容：旧版记录若把 `aria-label` 整句当成了 `key`，会按可访问名称前缀重新找到控件；`option` 中残留的 `, currently ...` 会先归一到当前值再匹配。账号隔离前的旧主机名记录只作为读取回退，账号内产生新记录时会被替换。
3. **去抖**：还原过程中的点击被 `applyingReasoning` 标记屏蔽，不会被当成用户操作而覆盖记录。
4. **可见性**：面板开关下方显示当前状态（`未记录` / `控件 → 路径 / 选项` / `标签（开\|关）`），并可一键清除当前账号与旧版主机名记录。
5. **边界**：平台未暴露开 / 关状态（没有 `aria-pressed`、`aria-checked`、`data-state` 或 active 类名）时只记录不还原，避免把用户的开关反向切掉；控件文案不随选择变化的平台只能靠"选项配对"路径记录。

元宝的记录与还原使用独立分支（`data-thinking-mode-switcher-trigger` 触发器、`aria-label="选择模型"` 父行、`aria-label="模型列表"` 子菜单、`data-input-label="model"` 模式文案）。还原先选模型，等菜单回到主面板后再选模式，最后打开一次主面板核对两个维度并收起；模式文案与模型文案分开读取，模型选择不会覆盖模式记录。`Hy4 preview` 仅提供专家模式，若记录里是 `Hy4 preview + 快速回答` 这类不兼容组合，脚本会在打开菜单前停止还原并在状态行说明原因。面板状态行显示 `模型 + 模式`，清除按钮同时删除新的选择记录和旧的推理记录。

面板开关「记住推理强度」控制整个功能，关闭后立即写入配置并停止轮询。

### 工具记忆

腾讯元宝的真实工具入口是输入框上方的原子工具行（`[data-new-input-control="atomic-actions"]`），专业写作、AI 生图等按钮直接带 `data-application-id`；放不下的工具收在同级的「工具 / 更多」菜单里。选中后，输入框出现一个可移除的芯片（`[data-new-input-control="selected-atomic-action"]`）。工具状态不跟着新话题或刷新保留，脚本记录当前芯片的 application id 与标签，并在输入框重建后恢复。元宝同一时间只允许一个原子工具，因此记录是单值，不再维护集合。

- **记录**：点击工具行后，在 120 / 320 / 700 / 1200ms 轮询输入框芯片，确认芯片的 `data-application-id` 与按钮一致后写入 `localStorage` 的 `ai_turbo_tool_memory`。点击芯片的移除按钮后，确认芯片消失再清空记录；未确认时保留原记录。
- **恢复**：页面加载与 SPA 路由变化后轮询等待原子工具行出现，最多约 28 秒。已经有匹配芯片时不重复点击；否则先找内联按钮，再打开「工具 / 更多」菜单找 `role="menuitem"` 行。每次点击后按 150 / 400 / 800 / 1400ms 验证芯片，失败会重试，最多 6 次。由脚本打开的菜单会在结束时关闭，失败时也不会留在页面上。
- **协调**：推理还原与工具还原共用一把互斥锁，推理优先。元宝存在待还原的模型 / 模式记录时，工具还原会等待推理还原结束再开始，避免两套弹层交叉开合；推理恢复因找不到触发器或超时退出时会释放锁。
- **隔离**：原子工具行、芯片和它自己的菜单不会被当作推理控件，工具点击也不会写进推理记忆。
- **兼容**：0.16.2 及更早版本按主机名保存的行标题集合仍可读取，首个标题会作为标签回退匹配；产生新记录时迁移到当前会话作用域并删除旧主机名记录。
- **边界**：恢复依赖 `atomic-actions`、`selected-atomic-action` 与 `data-application-id`。溢出菜单是否与静态资源中的同层 `role="menu"` 结构一致尚未在真实页面复核，属于待确认项；站点改版后可能需要在工具行里重新选一次以刷新记录。

面板开关「记住工具选择」控制整个功能，状态行显示当前记录并可一键清除。

### 会话历史检索

面板中的检索框在输入后经 100ms 防抖执行全文匹配，最多返回 10 条，每条显示消息序号与 180 字符预览。

点击结果会先把该轮标记为已恢复，再移除 `.ai-turbo-dehydrated` 与缓存的 `--turbo-cached-h`，随后关闭面板、平滑滚动定位并高亮约 1.8 秒。下一轮同步不会再把这条消息脱水。检索覆盖全部已索引消息，包括处于脱水状态的消息。

### 原始上下文导出

`复制原始上下文（回退）` 按钮会把全部消息按 `### 用户 / 助手 · Message N` 分段，输出为 Markdown 写入剪贴板。用于脱离脚本、把完整上下文粘贴到任意位置。

## 设计与实现要点

### 更新调度

页面变更由 `MutationObserver` 捕获。为避免观察自身写入导致的自激循环，脚本在修改 DOM 时进入 `selfMutationDepth > 0` 状态，观察回调直接跳过。渲染更新统一经 `requestAnimationFrame` 调度，最短间隔 **80ms**。

### 读写分离

所有布局读取（`offsetHeight`、`getBoundingClientRect`）集中在写入之前完成，写入阶段不触发回流读取，避免 Layout Thrashing。伪文件托盘的位置计算同样读写分离：一次性读取 anchor、input 与相邻兄弟节点的几何信息，算出最终位置后统一写入。

### 增量与全量同步

`turnIndex` 记录已索引消息。**全量同步**只在显式请求（选择器组切换、SPA 路由变化）时执行：清空索引后全部重建。其余结构变化（消息增删、顺序改变）只做**增量**：先删除已消失消息的条目，再为新增或 dirty 的消息抽取文本，存活消息复用旧文本，因此一条新消息的代价是 O(1) 而非 O(n)。选中 `getTurns()` 会逐条调用 `getComputedStyle` + `getClientRects`，这些结果在单个更新周期内被缓存（每周期开头清空），一次更新只付一次布局代价。选择器组按命中优先级依次尝试并缓存，SPA 路由变化时失效重选。

### 三重位置感知

伪文件托盘的位置更新由三套机制协同：

- `ResizeObserver`：捕捉尺寸变化（原生附件插入、输入框变高、composer 撑开）
- rAF 追踪循环：以 90ms 间隔捕捉纯位置变化（`ResizeObserver` 无法感知的平移）
- 视觉边界过滤 + `visualTop` 钳制（0.13.8）：前者剔除悬浮控件和过大的兄弟容器，后者兜底把 `visualTop` 钳制在合理区间，防止托盘因异常几何值消失或跳到视口外

三者都通过 requestAnimationFrame 合并到同一入口 `positionVirtualFileTray`，配合位置签名去重，避免重复写入与抖动。

### 输入框写入 `insertTextAtomic`

- **`textarea` / `input`**：使用 `Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype | HTMLInputElement.prototype, "value").set` 调用原生 setter 写入，保证 React 受控组件能感知变化，然后派发 `input` + `change` 事件。
- **`contenteditable`（ProseMirror 等）**：优先用 `document.createRange()` + `Selection` 选中编辑器全部内容，再 `document.execCommand("insertHTML", ...)` 插入，最后补派一次 `InputEvent`。`execCommand` 失败时回退为 `textContent = text`。

### 失败即回退

凡是涉及改写平台原生结构的操作（代码折叠、交接流程、发送按钮定位、消息回显胶囊）都遵循同一原则：**无法可靠识别目标时不做修改，保持原生行为，并通过状态提示告知用户**。交接流程额外保证：任何一步失败都把当前进度写入剪贴板，允许手动接续。

### 平台扩展

在 `PLATFORMS` 中新增一条平台定义即可接入新平台。`hosts` 与 `hostPaths` 同时驱动用户脚本头部的 `@match` 和运行时识别，不需要再改 `detectPlatform()`；消息根、代码卡片与动效差异用静态能力字段声明，识别后的分支只读这些字段，不比较平台名字。

| 字段 | 用途 |
| --- | --- |
| `hosts` | 平台所在的具体主机名；每个主机去重后生成一条 `@match`，运行时按同一份列表精确比对，需要覆盖的子域要显式列出 |
| `hostPaths` | 共享主机上的路径前缀，例如 `x.com` 仅 `/i/grok` 属于 Grok |
| `nativeTurnRoots` | 站点用自定义元素承载轮次并自带渲染框架 |
| `shellTurnRoots` | 轮次位于 shell / transcript 容器，需要先解析结构再回退到通用选择器 |
| `codeCardChrome` | 代码块带 ChatGPT 式外层卡片与头部工具条 |
| `quietMotion` | 流式输出会重绘整段会话，需要暂停宿主动效 |
| `turnSelectorGroups` | 多套消息节点选择器，按命中优先级尝试 |
| `turnSelectors` | 兜底消息选择器 |
| `userTurnSelectors` | 识别用户消息 |
| `userContentSelectors` | 用户消息内容容器 |
| `contentSelectors` | 助手消息内容容器 |
| `codeSelectors` | 代码块选择器 |
| `inputSelectors` | 输入框选择器 |
| `sendButtonSelectors` | 发送按钮选择器（会被 `findSendControl` 优先使用，未命中则走通用兜底） |
| `sidebar` | 折叠导航栏的悬停探出配置：选择器、触发按钮、探出宽度、折叠判定宽度、父容器裁切时的固定位移 `shift`、需要临时抬起内联隐藏声明的子节点 `reveal`；未声明的平台不启用 |
| `sidebar.shells` | 探出时需要一并拉伸的内部容器选择器；面板内容按折叠宽度排版时，只加宽导轨本身仍会被裁切 |

`findSendControl` 的通用兜底对所有平台生效，因此新平台未提供精确的 `sendButtonSelectors` 也可能通过 `form` / composer 容器 / 向上 8 层的 `isSendLikeButton` 命中。

## 已知限制

- 平台前端改版会导致选择器失效，需等待脚本更新；`findSendControl` 的多级兜底可覆盖部分小规模改版，但无法覆盖彻底重构的 DOM 结构。
- 脚本不申请 GM 权限，剪贴板写入依赖浏览器授权；无法写入时仅在状态栏与弹窗提示，不会抛错。
- 负载环仅按消息数量估算，与模型实际上下文容量无关。
- 伪文件覆盖文本键入与粘贴路径，不接管平台原生的图片与文档上传流程。
- 脱水消息内的交互元素不可点击，点击空白占位区或命中检索跳转会恢复该轮（恢复后不再回退脱水）。
- 代码折叠与交接自动化在平台结构大改时可能降级为无操作或复制到剪贴板，属于预期行为。
- 伪文件托盘的 rAF 追踪仅在存在虚拟文件时运行；页面极度繁忙（大量流式输出 + 频繁重排）时，托盘跟随可能出现一帧延迟，属于权衡选择。
- 已发送消息里的胶囊依赖页面中仍然存在的 token 文本：平台若把消息改写成图片、摘要，或卸载旧轮次，胶囊会随宿主一起消失；正文被截断时预览只会显示剩下的部分。
- AI 生成中若平台将发送按钮替换为"停止生成"按钮，脚本会通过 `isSendLikeButton` 的排除规则跳过；请等生成结束后再发送。
- 一键交接的等待交接包上限为 **3 分钟**；模型回答极其冗长时可能触发超时，此时生成指令会被复制到剪贴板供手动重试。
- 推理强度记忆的开关型控件依赖平台把开 / 关状态暴露在无障碍属性上；纯 class 切换的控件能识别 `active / selected / checked / is-on` 形式的类名，其余情况只记录不还原。选择型控件（如 Gemini 的模型 / 思考强度）不靠文案词表，触发器识别覆盖 `aria-expanded` / `aria-haspopup` 与 Angular Material / CDK 的自定义属性；选项行优先按单选语义（`aria-checked` / `aria-selected` / `role=menuitemradio`）识别，Gemini 这种只用 class 和选中图标的行也能配对。路径还原依赖每层子菜单有稳定的 `aria-controls` 与可见标题；触发文案无法唯一对应选项、且没有路径信息时，仍可能只记录不还原。页面刚打开、按钮尚未接上事件时点击不会生效，这类情况靠轮询重试（约 60 秒内），超时后需手动选择或刷新。
- 元宝的模型 / 模式还原依赖 `data-thinking-mode-switcher-trigger`、`aria-label="选择模型"`、`aria-label="模型列表"` 与 `data-input-label="model"`，并需要向父行派发指针移动事件才能展开子菜单。这些选择器与恢复流程已由静态 DOM 测试覆盖，并在 2026-11 的真实页面上复核：刷新后模型与模式都能还原，面板保持关闭。站点改版后可能出现只记录不还原，状态行会显示停止原因，重新在模型菜单里选择一次即可刷新记录。
- 工具记忆依赖元宝原子工具行的 `atomic-actions`、选中芯片的 `selected-atomic-action` 与按钮上的 `data-application-id`；这些结构改版时，可能只记录不恢复。溢出菜单的按钮文案与容器层级来自静态资源，真实页面尚未复核，属于待确认项；脚本不会凭空选择菜单中不存在的工具。
- 侧边栏悬停探出依赖平台暴露的折叠状态（类名或折叠宽度）来判断是否处于收起态；平台改版后若状态不再可辨，探出会静默失效，侧栏回到原生行为，不会误加宽已展开的侧栏。位移补偿在侧栏为 static / relative 且父容器是 flex / grid 行，或宽度跟随子级的 block 容器时自动生效；父容器裁切溢出的站点依赖 `sidebar.shift` 里的实测负外边距，站点改版后需要重新核对。ChatGPT 的内联隐藏声明若改由样式表控制，`reveal` 会退化为无操作，探出仍会加宽侧栏。`shells` 同样是按选择器匹配的，站点换掉内层容器后需要重新核对；未声明 `shells` 的平台只加宽导轨本身，内层内容是否跟随由站点自己的样式决定。

## 版本记录

### 0.20.7

**按下之后等一拍再交还，给站点留出挂载菜单的时间。** Qwen 的历史行操作按钮只带 `aria-label="Chat Menu"`，没有 `aria-haspopup`，也不在探出的弹层选择器里。上一版在同一次事件里交还探出并抑制重新打开，触发键还没等菜单挂载就被收回，菜单始终不出现，导轨约 1 秒后塌回原始宽度。

- **交还延后 140ms。** 菜单在点击的同一个任务里挂载，140ms 足够看到结果；历史跳转仍在 140ms 内交还，赶在下一个路由绘制之前完成收起。
- **交还前对比一次弹层快照。** 按下前后各取一次可见弹层集合，出现新弹层就保持探出；没有新弹层才按原路径交还并抑制到指针离开边缘。不靠 `aria-haspopup`、`data-state` 之类的标注推测。
- **挂起的交还随探出一起清理。** `releaseActive` 取消未触发的交还定时器，导轨关闭后不会再被旧定时器补一次收起。
- **无新增配置项。** 存储键、默认值与各平台参数不变，只新增常量 `SIDEBAR_PEEK_CLICK_RELEASE_MS = 140`。
- **实测结果。** 1440×900 真实浏览器：Qwen 收起 60 → 悬停 240，按下历史行操作按钮后 120ms、620ms、1520ms 均保持 240，菜单项为 置顶 重命名 克隆 归档 分享 批量管理 下载 移至项目 删除 举报内容，指针移出后回到 60。历史跳转收拢：ChatGPT 340 → 400ms 回到 52，Gemini 288 → 180ms 115 → 240ms 52，Z.ai 238 → 700ms 60，Qwen 240 → 600ms 60，此后 2.4s 内无二次展开，移出后保持收起。单元测试 478 项全过。

### 0.20.6

**让探出只在站点真的画出面板时保持，并把 Qwen 与 Z.ai 从纯 CSS 加宽改走原生展开。** 上一版这两个站点只声明了 `peekWidth`，探出在原有节点上强行加宽；空节点怎么加宽都还是空的。这一版补上 `nativeExpand`，并在按下之后复核站点是否真的画出面板。

- **按下之后复核两次。** 站点的展开控件有时候是惰性的：按钮在、按下无响应，导轨纹丝不动。现在按下后 320ms 检查一次，再 320ms 检查第二次，宽度离开收起上限或者状态标记为展开才算真的打开；连续两次没动就静默交还，既不留下一个空框，也不去按折叠键——那会把用户没打开的面板切一次。
- **替换导轨只采纳它自己画开的那份。** 历史跳转会让站点重挂导航栏，新节点可能已经收起。原先探出把旧的展开态直接转移过去，于是新节点挂着"已展开"的标记却被站点画成窄栏，指针移动时两种状态互相覆盖，看起来就是在正常侧栏与自定义侧栏之间抽搐。现在新节点没有画开、也不是刚那次按下的产物时，探出直接结束。
- **Gemini 的 `peekWidth` 由 248 改为 288**，与站点原生展开列宽一致：指针带覆盖整段动画期的可见列，移到动画中的面板上不再被判成离开。
- **Qwen 与 Z.ai 改走原生展开。** 收起态的 Qwen 导轨没有渲染历史行，纯 CSS 加宽只能在空节点上加宽，那就是用户看到的黑框；Z.ai 的行操作按钮由站点在展开态才挂载，强行加宽拿不到删除、重命名这些按钮。现在两者都按下站点自己的展开控件，面板里的内容由站点渲染。
- **无新增配置项。** 存储键、默认值、其余平台参数不变；改动只影响探出何时保持、何时交还。

### 0.20.5

**一次修掉悬停探出在所有站点上共有的四类缺陷：不触发、展开后面板不完整、面板中间的空隙导致收回、点历史跳转后收起卡顿。** 这轮的问题不在某个站点的选择器，而在探出对「站点自己也在改状态」的假设。

- **收起与否先看画面，类名只作兜底。** 每个平台切换都是先动宽度、动画结束才改状态类，反方向也一样：面板已经画开还挂着折叠类，刚关上的还留着展开类。先读类名会让探出对着已展开的导轨再按一次展开——站点把展开布局重画一遍，面板出来时内容不全——或者在站点已经收起时按空。现在面板在屏上就只按宽度判断，只有离屏、0 宽、滑出边缘时才回退到类名。
- **指针判定改成并集。** 原生导轨经常短暂失去矩形：整条滑出边缘（元宝）、保留 0 宽占位（Grok、Qwen）、或在站点切换的那一帧被卸载。原先只认实时矩形，指针明明停在自己刚看到的面板上也会被判成离开，表现为探出到一半就收回、或者移到面板中间的空隙就消失。现在实时矩形、最近一次绘制矩形、探出实际达到的宽度三者取并集，空隙与临时卸载都落在带内；面板被站点换成更宽或更窄的节点时同样成立。
- **历史跳转后等指针离开条带再探出。** 点击历史行会关掉探出打开的面板，而指针还停在被点的那一行上。原先下一次移动立刻重新排期，刚关的导轨又开，用户看到的是面板反复开合、怎么都收不干净。现在跳转与路由变化后进入抑制态，指针离开边缘条带的那一刻才解除。

- **展开控件先在导轨内部找。** 宽屏布局会给窄视口再挂一条导轨，全文档查找可能按到用户没看的那条，面板会开在别处。现在先在本条导轨内找第一个真正绘制的控件，再回退全文档。

- **子菜单父行不再强制要求 `aria-controls`。** 只写 `aria-haspopup` 的实现也能展开：子菜单里已有目标项就点它，否则弹层里只有一个可展开行时直接展开。
- **点击前补一个移入事件。** 部分菜单是悬停展开的，纯 click 不会开子菜单；现在先派 `pointerover` / `mouseenter`，再走原本的按下-抬起-点击序列。

### 0.15.5

- **修复：思考强度那一层根本不会被展开。** 0.15.3 选子菜单父行的条件是“它的 `aria-controls` 子菜单里已经能看到目标项”，但子菜单是点开才渲染的（默认 `display: none`，`data-visible="false"`），这个条件永远不成立。现在改成：子菜单里已能看到目标项就点它，否则只要弹层里只有一个可展开行就直接展开它，然后在子菜单里以 200ms 间隔最多等 7 次（约 1.4s）再找目标项。
- **子菜单查找补一条退路。** 有些实现把子菜单内联展开到父菜单里，不在 `aria-controls` 那个节点下，两种位置都会找。

### 0.15.4

- **修复：记住了强度但不会自动启用。** 选择型还原只有一次机会——`applyReasoningMemory` 在找到控件后立刻把 `reasoningRestoreDone` 置为 true，而轮询一旦看到这个标记就停止；首次展开弹层稍慢（Angular 首次渲染菜单需要几百毫秒）时，还原序列在空菜单上点空，然后被判定为“已完成”，此后永不重试。现在整串选择真正点完才算完成，失败会把标记复位，交给轮询在稍后重试。
- **等弹层的时间放宽到约 2 秒。** 250ms 间隔最多 9 次，替代原来 300ms × 4 次（约 1.2 秒）。
- **轮询上限 20 秒 → 60 秒**（40 → 120 次），覆盖页面初始化慢的情况。
- **还原进行中不再重入。** 上一轮序列未结束时轮询直接跳过，避免两次还原交叉点击同一个弹层。

### 0.15.3

- **修复：Gemini 的思考强度还原不生效。** 强度选项在二级子菜单里（`Thinking level` → `aria-controls` 指向的 `gem-menu`），0.15.1 / 0.15.2 只在打开的弹层顶层按文案找选项，永远找不到；模型行文案还带版本号前缀（按钮写 `Flash`，行写 `3.8 Flash`），等值匹配也必然落空。0.15.2 的“记录文案包含选项文案”宽容匹配对选项过多时同样无力。

- **多段文案逐层还原。** 触发器文案是多段（`Flash High`）时按词逐个点：先选模型，再重新展开弹层选强度；没找到就关掉弹层退出，不留遮挡。
- **防御。** 子菜单层级上限两层，并有 `shortcut:` 注释标明升级条件。

### 0.15.1

- **安全：只认同弹层触发器。** 无关键词的点击若控件不带 `aria-expanded` / `aria-haspopup` 就不记录，避免把`发送 → 停止`这类文案变化误当强度选择并在下次启动时回放。
